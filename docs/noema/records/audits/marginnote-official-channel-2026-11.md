# Noema 官方插件通道复核

日期：2026-11-05。接续[首次安全审计](marginnote-plugin-audit-2026-11.md)，当前契约见
[接口设计](../../design/marginnote-agent-bridge.md)。未修改 MN 应用本体、直接写资料库或绕过认证。

## 本次真机证据

Mac MN 5.0.1 build 50100 / Bridge 0.93，现有 Noema 1.0.3 身份 `noema.extension.agent`：

1. 从真实插件 owner 调用 `AddonWebPanel.panel()`，得到带 `loadHTML/loadPanel/onMessage/showFloatingIn/teardown` 的面板。
2. 用内联只读测试页与本插件 `onMessage` 打开面板，`floatingVisible:true`。
3. 官方 `POST /bridge/v1/addons/noema.extension.agent/panel/eval` 提交页面的 `fetch('/addon/ping')`。
   同步返回 accepted；第二次 eval 读异步结果，得到 `{native:true,echo:{proof:42},appVersion:"5.0.1",ok:true}`。
4. teardown 临时面板。随后无令牌/错误令牌均 401；有效令牌进入处理器，面板已关返回 409 `PANEL_NOT_OPEN`。

因此官方认证 → 同一插件面板 → 原生回调 → 官方结果的只读链路成立。它不是新正式包安装验收，
也不是精确批注已经通过这条新传输写入。此前真实批注仍是旧通道的证据。

## 正式源码与安全收敛

同一 Noema 升至 1.0.6，默认包仅有 `main.js/mnaddon.json/panel.html/icon.png`，无地址、令牌、
外部页面资源或新监听。明确 `--legacy` 才嵌入旧私有配置。host 下次启动默认不创建旧监听或令牌，
仅 `NOEMA_MN_LEGACY=1` 开启；发布 server 模式仍禁止。当前旧 host 尚未重载，不能把默认值当运行事实。

- 官方 Node 客户端读取明确设备的已有凭据，校验真实私有 IPv4（拒绝 `192.168.attacker.example` 一类域名），
  路径固定 `/bridge/v1`，不跟随重定向。旧通道只有显式选项，失败不自动切换。
- 页面只接受固定的 status/submit/result 信封；原生执行仍完整开放 JSB，未制造一个虚假的权限沙箱。
  页面 CSP 不加载外部内容；原稿内容仍是数据，不能提升为执行授权。
- submit/result 检查 native sessionId，避免换窗口后写错。忙时拒绝新任务，没有后台执行队列。
  同 ID 同内容复用结果，冲突拒绝；回调先返回，再调度用户代码。超时不重放、不强制终止副作用。
- 代码和 args 各 256 KiB，原生值 1 MiB；完成任务 payload 合计 8 MiB、最多 32 项/15 分钟，
  另保留 256 个淘汰 ID。页面回执最多 16 项/4 MiB，原生 HTTP 回调 10 秒后报告未知。
  缓存有界且易失，仍需业务层 plan/source 身份及写后回读。
- 空闲不发请求、无周期定时器；复用已核对的 sessionId 可省去每任务的两次状态 HTTP 请求。
  仅运行中的请求按短延迟逐步退避查询；status/exec 不偷偷打开 UI，open 是明确动作。

## 部署边界

已通过 MN 正常打开同 ID 安装包。原生 UI 实际读到 `UIAlertController`，提示“插件已存在，是否替换？”，
按钮为“是／否”。当前工具没有正常点击通道，已请用户完成该原生确认；没有调用私有 reload、
直接覆盖已安装文件或新建另一个插件身份来绕过。在线 1.0.3 不能代表源码 1.0.6 已生效。
安装后需同时读 manifest 和实际加载源码/运行回执，核对最新构建摘要，不能只看版本号。

仍待：正式包 exec 的真机全程、安装后的关闭重开/暂停行为、iPad 现场执行及同步、批注自动跟随移动。
手写/图片/卡片的局部读取和原生精确摆放既有能力不受这些未验证项代替。

## 局部批注复查补充验收

新增 skill 工具 `mn_annotation_state.mjs/.js` 与 `mn_annotation_follow.py`，读取当前已接受区域的
原生卡片布局和官方源库存，检查已有批注是否仍对应原来的图文。流程不写 MN、不跳转界面、不下载媒体或调用 OCR。
原生脚本限 Mac 5.0.1 build 50100；通过已有旧通道取得真实布局，不将其算作正式 1.0.6 的运行验收。

- 布局从已验证 UIView 路径读取，按 `allBounds` 剪去区域外分支。最多 96 个视图、512 个布局节点、
  64 张局部卡；仅点名且在区域内的卡读取正文与关系，正文、评论数和关系数据也有上限。
  预算耗尽返回覆盖不足，不能用部分结果判定空白。宿主可能重算脏分支范围，尚无真实大图延迟基准。
- 原生状态只接受 15 秒内的回执；前后两次官方库存核对源实例、身份与局部范围。相关图片与笔迹必须
  共同平移，卡片标题、正文、尺寸和上次位置仍一致，目的地在已读范围内且不碰撞，才提出平移建议。
  更新标识不依赖可重排的 index/contentPath。所有建议均 `writesToMN:false`、`writeReady:false`。
- 图文分离、换图、重复来源、用户编辑或移卡、目的地越界、检测中变化均保留原卡。库存未暴露的旋转、
  绑卡变换和未保存笔迹不在本次保证内；真正写入仍需核对这些条件、Undo 组更新位置及关系、实际 frame 回读。
- 发现首张真实批注的旧 `textSHA256` 使用“标题＋换行＋正文”，现按这个精确格式兼容；新关系分别保存
  标题与正文摘要。没有通过规范化或忽略标题来掩盖用户编辑。

真实 Search/Count 批注的只读验收：16 个 UIView、8 个布局节点、7 个远处分支被剪去，只返回 1 张卡，
局部覆盖完整；官方 6 次请求、60 项轻量库存、0 下载/解码/OCR，结论为源与卡片均未变化。
本轮 Python 71 项、原生脚本 VM 5 项及 skill validator 通过。测试覆盖区域外父卡不能泄露正文、
区域内子卡不能因父卡在外而漏读、预算耗尽、图文分离、歧义身份、用户编辑、碰撞和稳定更新标识。
没有为测试移动用户原稿，也没有把只读建议当作自动跟随完成。

## 原生位置工具补充验收

skill 新增 `mn_annotation_position.mjs/.js` 和 `mn_annotation_source_check.py`，将单卡已有位置的
更新接到原生执行器。复查的 `--position-request` 可生成对应输入；工具分别提供只读 check 与实际 apply。
默认官方通道，以下真机验证仍显式使用在线 1.0.3 的旧传输，不算正式新插件部署。

- 自建测试卡从 `(11449.75,11099.5)` 移到 `(11529.75,11139.5)`，两次实际 frame 读回均为预期；
  尺寸保持 `700×562`。随后只在测试卡仍匹配本次写入时恢复原位，恢复 frame 一致。
  另在同一同步调用中测试位置＋`canvasAnnotation` 的共同 Undo，二者均恢复，未让用户操作插入撤销栈。
- 真实 Research 批注只做 check：即时读局部卡与两个点名笔迹的原生身份/矩形/根画布绑定；
  官方前后复查相同局部，0 媒体下载/解码/OCR。该批注未移动，用户原稿未改变。
- 新增写前旧值检查、原生来源结构检查、冲突与预算限制、保存后的模型和实际 frame 回读；
  requestId 和意图先以私有文件保存，未知结果不重试。关系与位置同 Undo 组，保留 `mindpos` 尺寸后缀。
- 检查发现 `notesText` 只涵盖评论正文，普通卡的文字可能在 `excerptText`。补充摘录文字和修改时间
  比对，并拒绝未适配的摘录图片；不以评论摘要掩盖其他内容变化。新关系分别记录标题、评论和摘录摘要。

当前仍只承诺已保存的根画布素材及已验证自由定位节点。native comments getter 可能整体物化 owner 的
轻量 metadata，代码限 256 项后停止；尚不能给巨大单 owner 画布的内存/延迟承诺。未保存笔迹、实际图文
移动后的整条跟随、iPad 和后台监听仍待验收；笔迹移动可能换媒体 hash，必须重新核对语义。
测试结束已恢复原学习集、焦点和选中卡，重新通过正常安装器打开待升级包，没有绕过其原生确认。

同轮检查还发现 Python CLI 仅用字符串前缀判断设备。已补成解析真实主机/端口/路径的校验，Mac 限回环，
iPad 限 RFC1918 IPv4，拒绝 userinfo、仿冒私网域名、异常路径/端口和令牌格式。隔离用例证明错误配置在
构造网络连接前被拒绝，未向外发令牌；有效 Mac 凭据重新连接与鉴权通过。这是配置误用风险收敛，不是声称外部攻击者能修改凭据文件。

本轮 Python 86 项、原生脚本 VM 24 项通过；skill validator 通过。覆盖摘录/格式编辑、来源变更/重复/绑定、
未知变换、越界/碰撞、尺寸后缀、同次操作不重复写及复查到写入请求的衔接。
真机与隔离测试回执保存在 `var/noema/marginnote/annotation-writer/`。

## 图片特征批注的实际创建与恢复

新增 skill 创建工具，将接受的局部方案接到 Noema 原生创建、实际尺寸适配与官方回读。
同一通道仍是在线 1.0.3；正式 1.0.6 安装替换确认待完成，以下结果不算新包或 iPad 验收。

- 鳄鱼参考照片与真实红圈的已核对关系被完整复用；保留 `perspective-corrected-photo-reference`，
  没有将照片改称官方原图，官方图片仍导出白 PNG。仅向右扩读 200 个画布单位确认空白。
  扩大后的窗口命中 4 个笔迹缓存、下载 1 个 26,593 字节图片，未调用 OCR；单图输入未变，只更新局部背景视图。
- 真实 Research 草稿根新增独立卡 `2850056F-96B9-4E56-984C-85D6BC7CB842`，
  标题“Agent 批注｜图中双眼”，正文“两个红圈分别对应鳄鱼的两只眼睛。”。
  实际 S 矩形 `(-29267.7177734375,-23974,700,336)`，横向误差约 0.003，纵向 0；
  关系记录由预估 700×552 更新为真实尺寸。原生 frame、来源关系、官方正文和单卡 render 均通过。
  单卡 render 只证明文字显示，不代替整张脑图截图；用户原图、字迹未移动。
- 草稿根用 `canvasAnnotation.<planId>` 单键记录预留、创建 ID 和初始版本，避免全子卡扫描。

  创建/初始关系和后续实际尺寸/位置最终调整是两个 Undo 组，不能声称整套操作一次撤销。
  生产工具不自动调用全局 Undo。测试后恢复原学习集、焦点及选中卡，经正常安装器重开待升级包。

首轮真实图片创建在写入前发现库存身份问题：官方 highlights 中无矩形的已解析素材引用与 notes 中
有矩形的图片实例同 hash，原先被源复查误算成两个实例。源检查及只读跟随现只用有矩形的实例判断唯一性；
仍拒绝两个实际放置的同源实例和无法解析的无坐标内容，没有通过任选一项来跳过歧义。
