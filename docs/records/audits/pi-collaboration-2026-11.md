# 项目协作：Pi、观察项与上下文占用（2026-11-02）

接续 [PlanWeave 与 Trace Canvas 审计](../../noema/records/audits/planweave-trace-canvas-audit-2026-11.md)。
这里记录这一轮的设计收敛、实测查出的问题和当时的占用数字，不作为现行约定。现行约定见
[Pi 的观察项](../../design/pi-watches.md)和 [Pi 会话](../../design/pi-sessions.md) C22。

## 设计怎样收敛

| 版本 | 执行者 | 项目范围 | 结果 |
| --- | --- | --- | --- |
| 1 | host 内常驻观察者，项目列表落盘 | 所有登记项目 | 530 行，host 替关闭的项目干活 |
| 2 | host 内，Emacs 同步打开的项目 | Perspective | 仍在 host 和 Emacs 各留一份状态 |
| 3 | Pi 插件，随项目 Pi 会话启停 | 运行中的项目 Pi | 337 行，host 和 Emacs 无状态 |

上一份审计以“要写用户的全局配置”否决了 hooks。否决的是位置，不是能力：观察项目日志的 hook 不碰
任何 Agent 的配置，对所有 Agent 一样。

host 过期后的自动重启做过又撤掉：host 是否重启由人决定，不值得为它多一份判断逻辑。

## 上游取舍的修正

| 上游做法 | 这里 |
| --- | --- |
| 各家 Agent 的 hooks 写入全局配置 | 改为读项目日志；不读对话流水 |
| 常驻协作服务 | 不要；Pi 是手动启动的，它在时才有后台能力 |
| 轮询状态 | `fs.watch` 加一个定时器；回复靠消息排队，调用方结束回合等待 |

## 实测查出、单元测试没发现的问题

用两个真实项目 Pi 往返一次：

- 消息头只说明回复给谁，Pi 花 6 次工具调用才找到接口。现在消息头给出可直接使用的调用。
- `describe` 写“按位置传参”，而参数是一个对象，Pi 用错后放弃，把回复写进自己的聊天。现在单对象接口
  会明说。
- 文档写 `emacs:agent`，接口只认全名，服务端修过之后客户端仍然拒绝。现在客户端规范化一次。
- `json-serialize` 返回字节串，buffer 名里的 `·` 混入提示词，请求发不出去，回合永远等待。单元测试的
  buffer 名是 ASCII，所以没发现。

- Pi 把参数压成值的列表，`emacs:agent` 读不到 `action`，按默认的 `list` 执行并答 `ok:true`，回复丢失却
  报告成功。现在只收一个对象的接口拒绝列表，工具说明也改了。这是这一轮最危险的问题：不是失败，是假成功。
- 回复进入对方会话时显示成 `You`，看不出来源，对方又回了一轮。现在回复模板带来源。

修完后往返一次：B 用 2 次工具调用，没有失败，回复到达 A。

另外，Pi 扩展的 `/` 指令不会被 pi-acp 公布，输出也不转发，所以管理指令放在 Emacs 动作表。

## 真实 Agent 的完整链路

临时 Noema Project 里的真实 Codex 会话：入口提示 → 读 `noema-pi` → 带 `from` 找 Pi → Pi 的回复进入
Codex 会话，带来源标记 → Codex 回应，排队和回合都正常。Pi 把“回复 pong”理解成转述这句话，修改模板
和提示词后不再出现。

真实 Claude 会话同样走通。Pi 的回复正好是 `pong`，但没有来源标记：用户请求“只回这个词”，模型就把
模板里的标记省了，Claude 因此不肯把它算作 Pi 的回复。这种事不能靠模型，现在由 MCP 入口加标记。
