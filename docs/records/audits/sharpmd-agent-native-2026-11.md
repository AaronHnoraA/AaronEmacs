# SharpMD 与 Emacs 原生文档协作

本轮阅读与验证：2026-11-19。用户目标是深化 Emacs-native 的 Agent / LLM
协作，让日常操作省事、结果可检查、长时间使用后仍能接续。本文记录源码学习、
实际改动与验证边界；现行契约见 [Agent 管理](../../design/agent-management.md)、
[Pi 提示词分层](../../design/pi-sessions.md)与
[批注](../../noema/design/comments.md)。

## 设计理解

结合现有架构、开发契约与用户本轮要求，我把设计哲学理解为：工作从正在阅读的
文档原处开始，结果留在所属文档；Emacs 管理编辑与执行资源；界面提供观察和介入
的入口。Markdown、批注日志、原生会话分别保有自己的权威。

这要求常用操作直接可做，语义 API 负责保存和刷新，Skill 只补深入判断。后台工作
不因侧栏收起而消失；文档、批注、会话有各自身份。状态、错误和验证依据必须能
回到实际对象，不能把模型的聊天结尾当作文件已改好或用户已批准。

SharpMD 的 agents 界面在可见时按 5/15 秒轮询。Emacs 已有真实进程与 ACP 事件，
继续复用事件和会话池。SharpMD 的引文会归一化空白并截短，适合显示定位；我们的
引文还要用于精确编辑，因此短引文保留原始字符，摘录明确要求另读源码。

## 本轮落地

1. 项目、页面与 LaTeX 修复入口先解析并引用客户端 Node 路径。测试在没有 Homebrew
   PATH 的 shell 中执行生成命令，还覆盖项目路径中的中文、空格、引号和 shell 字符。
2. 批注派工的短引文上限为 1200 字符，CJK 按字符计算，不按显示宽度截断；两种发送
   路径使用同一规则。更长的文本明确标为摘录，要求读取后再构造 `oldText`。
3. 工具指南明确翻译、润色、精简直接编辑，额外改动或明确审阅请求才提案；保留
   `{==text==}{>>#id<<}` 标记。这里是对 Agent 的指导，未新增通用编辑 API 的强制锚点保护。
4. Emacs 与 Noema 按文件和 id 查询、写入批注。兄弟文档不能读、结案或改派别篇任务；
   同目录 id 冲突仍被拒绝。跨目录迁移辅助函数先检查目标日志，发现 id 冲突时两个日志都不改；
   该函数尚未接入普通文件移动，不能据此声称实际移动已具备自动任务迁移。
5. 看板重绘保存任务身份。前面插入卡片后，下一次键盘操作仍指向原任务；任务不在
   当前视图时退出卡片选择。任务定位在泳道或 Agent 行停止，泳道标题不向上操作上一项
   任务。等待卡片复用已有快照展示具体请求或错误，悬停可读完整文字。

保留 `oldText` 的原因是它还能发现用户刚改过的文字。仅按 `commentId` 定位不能提供
同样的内容守护；本轮没有为了减少一次读取而增加会覆盖陈旧内容的快捷写入方式。

## 验证与范围

修改前已用失败测试复现命令找不到 Node、短引文截断、兄弟文档访问、移动冲突、
刷新后选择改变、等待原因缺失。独立代码审查补充了空行上的有效选择问题：操作会向上
寻找任务，重绘也必须沿用这一身份；强化后的测试覆盖卡片内、卡片后空行与任务消失。

最终验证：

- Noema 固定工具链：`PATH=~/.nvm/versions/node/v26.5.0/bin:$PATH make test`，
  357 个文件通过、7 个跳过；3683 项通过、17 项跳过。
- `make install`（包含 renderer / kernel build）通过，使用同一固定工具链。
  当前默认 shell 是 Node v26.13.0，最初构建在版本检查处停止；没有修改全局环境。
- `make research-test` 全部通过，各组为 2、321、29、96、113 项；最终面板边界修改后，
  另跑 panel / collab / context / hy-memory 四文件 ERT：93/93 通过。
- `make jupyter-test` 与 kernel 的 `go test -tags fts5 ./...` 通过。
- `make state-baseline` / 最终 `make state-check`：启动快照均为 19447 行，差异为零。
- 独立代码审查的两项选择/边界回归 2/2 通过，没有剩余阻断发现。

一次与构建及其他测试并行的固定版本全量运行中，`drag-select-cost.test.ts` 的公式
拖选 p95 为 24.37ms（阈值 22.22ms），`large-document-perf.test.ts` 的 org-env
标题修改为 483.10ms（阈值 480ms），两项失败。其他并行工作结束后，全量重跑通过；
未修改测试阈值。不能据此声称已经证明这两项计时稳定，仍保留这次失败记录。

执行日志位于 `/tmp/emacs-agent-*.log`；它们是本机临时核查材料，以上命令与结果为
持久记录。没有启动新的 Emacs 或改动正在进行的 Agent 对话。
Noema 侧代码与测试提交为 `e4affce`；Emacs 侧代码与本文在配置仓库独立提交。

本轮没有把现有批注迁移为持久的 Todo / Doing / Review / Done 协议。
现有 C81 泳道仍根据批注与接手会话快照投影，不能证明每一项任务各自的执行进度。
独立 attempt、交付版本与人工 Review 的设计仍在工作区草案中；不能把这些目标说成
已经实现，也不能仅凭会话空闲就自动结案。

跨目录冲突检查是预检，不是两文件事务，也不保证与外部进程同时创建相同 id 时互斥。
本轮没有验证真实远程网络、浏览器焦点、完整桌面产品交互或修改全局 Node 设置。
