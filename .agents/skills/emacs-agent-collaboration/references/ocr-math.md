# OCR 与数学答疑分工

用户同时要求识别和讲解时使用这条流程；只要 OCR 就只交付 OCR。数学 Agent 可以是
当前主 Agent，也可以是另一个 worker；它不同时承担整份原稿的识别工作。

## 输入与目录

先从用户请求、当前文档和现有 MarginNote 接口取得设备、原生笔记身份及页/卡片范围。
只在这些信息仍不足以定位时询问，不让用户手工导出已经能通过接口取得的材料。

复用 `marginnote-digitize` 的工作目录和断点：官方 PDF、页映射、裁图、候选与逐页
草稿留在那里。正式转写与答疑各有文件；指定已有 OCR 目标时只更新请求范围。
没有明确目标时先做独立草稿，不把证据附件和运行信息塞进正文，不覆盖人工改写稿。

## OCR worker 的任务

派工时带上原生来源与范围、输出路径及 `marginnote-agent`、`marginnote-digitize`
的可读入口。让它先执行现有 `workflow.py env`，按其返回定位工具和权威语法。
需要某项能力而不可用时，返回该项失败和已保存的部分产物，不把空结果当作没有笔记。

交付忠实转写及来源记录：每页/卡片或区域能回到原生身份和对应 PDF 页，歧义记录
给出所在位置、局部图和候选。复用 OCR skill 的逐页落盘和 Mathpix 缓存；不要求每页
重导 PDF，不为证明能通过而修正原稿数学内容。清楚的原稿照录，读不清按该 skill 标记。

可用派工说明：

> 读取指定设备上的这份笔记，仅覆盖指定范围。使用 marginnote-digitize，把转写写入
> 约定路径，保留来源页映射及疑点局部证据。不要补证明或改正原稿数学。最终返回交付路径、
> 实际覆盖范围、尚未辨清的位置和做过的检查；不另给父 Agent 发消息。

## 答疑 Agent 的任务

主 Agent 先检查转写和范围，再给答疑者用户的问题、转写文件、来源记录和疑点证据。
答疑者区分“原稿写了什么”和“数学上怎样成立”，解释、修正和补充写在答疑文件里，
不改忠实转写。检查问题所依赖的定义、假设和公式，不将一页 OCR 的完成当作全书覆盖。

若一个符号会改变推导，只向 OCR worker `send` 对应原生位置和裁图的复核任务；
仍辨不清时保留候选，在明确假设下分别推理，不用 Lean 能否证明来替代字形证据。
有争议的前提未定时，可以完成不依赖它的解释，但不把依赖它的结论报为已验证。

Lean 按需辅助：先读取可用的 `lean-proof`／`lean4`，复用用户的 Lean 项目与工具链。
保存命题、假设、证明文件、实际检查命令和结果。工具不可用或尚有 `sorry`/未处理错误时
如实记录，不声称形式化验证完成；原稿未给出的额外公理或假设需要明确披露。
不要为简单解释自动下载或构建整套 mathlib。

## 合流

核查转写覆盖、重要歧义、答案对原稿的引用，以及声称执行过的 Lean 检查。
向用户直接给出答案与产物入口，保留影响结论的未决点；不把内部轮询、session ID
和 worker 互相确认的消息交给用户处理。
